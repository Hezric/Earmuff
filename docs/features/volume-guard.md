# Volume protection

Earmuff watches the Windows default render endpoint (`eConsole`) through Core Audio device and endpoint-volume notifications. Audio writes are serialized on one COM worker behind `AudioBackend`. For a protected output, a rounded full-volume reading (99.5% or higher, matching the prior tool's rounding) drops to the configured drop level; other readings above the cap clamp to the cap. Unprotected outputs receive no writes. Pausing stops writes for the saved duration (60 minutes by default, 1–720 whole minutes) using a monotonic deadline; resume enforces immediately. Restarting resumes protection.

Settings use `%APPDATA%\Earmuff\Earmuff.ini`, with defaults defined in `src-tauri/src/settings.rs`. Device sections use hex-encoded stable endpoint IDs. New outputs are protected. Software and display outputs stay under Other devices even after use as the default; expanding the group exposes the same individual protection switches as the main list. Classification uses Windows device ancestry and endpoint form factor rather than friendly-name matches. Software audio under `ROOT` and display audio fold into Other devices. Physical USB speakers stay in the main list. If classification metadata is unavailable, leave the output in the main list with protection on.

Malformed settings activate safe defaults and show an error without silently overwriting the original file during discovery. User edits write a replacement through a synced temporary file. Save and audio errors are visible in the flyout and tray tooltip.

The resident app owns a tray icon and notification worker, with no initial webview or login registration. Opening from a tray click, the Open menu item, or a second launch dispatches webview creation off the synchronous event handler so Windows can keep processing WebView2 messages. After its first presentation, focus loss, Escape, or close destroys the flyout. The flyout follows the system theme and accent. Its footer gear swaps the device list for protection, pause-duration, language, and about settings. The presets (15, 30, 60, 120) precede the minutes field; Enter or focus loss saves valid input, while invalid input keeps the previous saved duration and displays an inline error. Changing the saved duration leaves an existing pause deadline intact. Settings offer system, English, or Simplified Chinese language; the default follows the Windows display language. Inter and a subset of Noto Sans SC are bundled locally; device names fall back to system fonts. The taskbar theme selects the monochrome tray icon independently of the app theme: headphones with a solid shield when the current output is protected, half-opacity headphones when unprotected or absent, and two pause bars while paused. Tray artwork uses separate pixel grids for each raster size, with headband width and weight calibrated against Windows Wi-Fi captures in both modes. Windows 11 Default uses 16-DIP artwork; Small uses 12-DIP artwork inset inside the unchanged 16-DIP app-image box. The resident worker checks the taskbar size, theme, and monitor DPI once a second while idle, without audio work or a webview. The size setting is read from `Explorer\Advanced\TaskbarSize` (0 Default, 1 Small), an undocumented Windows shell contract; unrecognized or absent values use Default. The flyout centers horizontally on the tray icon on its monitor, with a scaled gap above the taskbar and clamping to the monitor work area. Both main and settings views fit their content with equal footer padding. Visible changes use 200 ms ease-out motion: the native flyout fades and slides on opening and dismissal, settings and Other devices interpolate height, and controls, status text, device-list updates, and errors cross-fade or transition. The complete panel animates inside a stable transparent native viewport; a native region clips drawing and hit testing to the panel and its CSS shadow, keeping the taskbar edge anchored without resizing WebView2 each frame. The height limit comes from the monitor work area; on a constrained display the body scrolls while the footer stays reachable. Windows Animation effects controls native motion through `SPI_GETCLIENTAREAANIMATION`; the webview follows `prefers-reduced-motion`, including live changes, and completes changes instantly when motion is disabled. Dismissal destroys the webview after its exit animation.

`npm run dev` is a browser-only mock preview and never accesses Windows audio. `npm test` checks the browser model. `cargo test --manifest-path src-tauri/Cargo.toml --locked` uses simulated audio. The ignored `audio::tests::enumerate_only` test reads endpoint metadata only; running it explicitly never reads or writes volume or starts the app. Real notification latency, tray placement, live taskbar changes, and webview release require an authorized native session.
